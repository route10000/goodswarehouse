# GoodsWarehouse

Учёт грузов из Китая для перевозчика, который возит их своими машинами
из Уссурийска на склад во Владивостоке.

Версия 1.0.0.

## Какую задачу решает

Раньше телефоны клиентов хранились в бумажных тетрадях, и каждый день сотрудники
обзванивали всех подряд: «ваш груз приехал», «груз ещё в пути», «заберите груз,
хранение заканчивается». Половина звонков была лишней, а часть клиентов не дозванивались
неделями.

GoodsWarehouse берёт эту рутину на себя:

- клиент один раз подключает Telegram-бота и сам получает сообщения, когда машина
  выехала и когда груз можно забирать;
- сотрудники каждое утро получают **ордер на день** — список только тех, кому
  действительно нужно позвонить (нет Telegram, сообщение не дошло или груз долго
  лежит на складе),
  отмечают «позвонили» / «не дозвонились», печатают его или выгружают в Excel.

## Возможности

**Публичный сайт**
- главная со статусом маршрута, ближайшими машинами, условиями и частыми вопросами;
- расписание машин и прогресс рейса;
- «Где мой груз» — поиск по коду клиента или артикулу и последним 4 цифрам телефона;
- контакты склада и вход для сотрудников.

**Telegram-бот**
- привязка клиента по ссылке или по номеру телефона;
- уведомления: машина выехала, груз на складе, напоминание, хранение заканчивается;
- «Мои грузы» и «Расписание» по запросу.

**Панель сотрудников** (`/panel/`)
- **Ops-центр** — KPI, конвейер статусов, схема маршрута с машинами, таймлайн дня;
- **машины** — создание, отправка и прибытие с подтверждением последствий, таблица грузов;
- **импорт манифеста из Excel** — предпросмотр с ошибками по строкам, затем атомарная загрузка;
- **ордер на день** — формирование, отметки звонков, печать A4 и выгрузка в Excel;
- **выдача** — поиск клиента по артикулу, телефону или коду и выдача нескольких грузов сразу;
- грузы и клиенты с поиском; роли «Менеджер» и «Склад».

## Стек

Python 3.12, Django 5.1, шаблоны Django + HTMX, чистый CSS на токенах.
SQLite для разработки, PostgreSQL в продакшене. Тесты — pytest, линтер — ruff.

## Быстрый старт (Windows, PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
$env:DEBUG="true"
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_demo
.venv\Scripts\python manage.py runserver
```

- Сайт: http://127.0.0.1:8000/
- Панель: http://127.0.0.1:8000/panel/ — логины `manager` (Менеджер) и `sklad` (Склад).
  Пароль демо-пользователей — `demo12345` или значение переменной `DEMO_PASSWORD`.
  Это только для локальной работы: на боевом сервере задайте свои пароли.
- Пересоздать демо-данные: `.venv\Scripts\python manage.py seed_demo --reset`.

Настройки читаются из переменных окружения, полный список — в `.env.example`.
Без `DEBUG=true` обязателен `SECRET_KEY`. Без `TELEGRAM_BOT_TOKEN` отправка
уведомлений работает в режиме dry-run.

Фоновые команды: `run_bot` (бот), `send_notifications` (отправка очереди),
`daily_reminders` (напоминания), `build_daily_order` (ордер на день).
