# GoodsWarehouse v1.0 — спецификация

## 1. Проблема и цель

GoodsWarehouse — посредник: грузы клиентов приходят из Китая в **Уссурийск**, оттуда наши машины (рейсы) везут их на склад во **Владивостоке**, где клиент забирает груз. Сейчас сотрудники пишут телефоны клиентов на листочке и каждый день обзванивают всех, чтобы те приехали.

**Цель v1.0:** убрать бумажный обзвон.
1. Все клиенты, грузы и машины — в одной базе, а не на листочке.
2. Когда машина выехала или прибыла, клиенты получают сообщение в Telegram **автоматически**.
3. Клиент сам видит статус своего груза и расписание машин на сайте и в боте.
4. Вместо листочка каждый день формируется **ордер на день**: таблица «артикул · телефон · вес · мест · статус (позвонили / не смогли дозвониться)». Сотрудник отмечает результат в один клик, ордер можно распечатать и выгрузить в Excel.

## 2. Не входит в v1.0

- WhatsApp и SMS (заложена абстракция канала, подключим в v1.1).
- Онлайн-оплата, учёт финансов, бухгалтерия. Сумма к оплате только отображается.
- Личный кабинет клиента с паролем. Груз ищется по коду клиента и телефону.
- Выкуп товаров, работа с маркетплейсами, склад в Китае как отдельный модуль.
- Мультиязычность (только русский), мобильное приложение.

## 3. Стек

- Python 3.12, **Django 5.1**, шаблоны Django + **HTMX 2.0.3** (лежит в `static/vendor/`), без сборки фронтенда.
- CSS: свой, на CSS-переменных (`static/css/tokens.css`, `app.css`). Шрифты: Google Fonts — **Onest** (заголовки 800, текст 500/600; хорошая кириллица) и **JetBrains Mono** 600 (артикулы, телефоны, цифры).
- БД: SQLite в разработке, PostgreSQL 16 в проде. Выбор через `DATABASE_URL` (`dj-database-url`).
- Telegram: Bot API напрямую через `httpx` (без фреймворка бота), long polling.
- `phonenumbers` (нормализация +7), `openpyxl` (импорт манифеста машины из Excel).
- Тесты: `pytest` + `pytest-django`. Линт/формат: `ruff`.
- 3D-сцена Ops-центра: **three.js r160** (ES-модули в `static/vendor/three/`), данные из JSON-эндпоинта панели.
- Фоновые задачи: management-команды, их запускает cron или systemd-таймер. Celery в v1 не используем.
- Прод: gunicorn + nginx на VPS, `whitenoise` для статики.

## 4. Архитектура (Django-приложения)

| Приложение | Ответственность |
|---|---|
| `config/` | settings, urls, wsgi |
| `logistics` | модели Client, Truck, Cargo, DailyOrder, DailyOrderLine, ContactAttempt; доменные сервисы (`services.py`): смена статусов, каскад, выдача, импорт манифеста, формирование ордера (`orders.py`) |
| `notify` | модель Notification, тексты сообщений (`messages.py`), постановка в очередь, отправщик, Telegram-клиент, команды `send_notifications`, `daily_reminders` |
| `bot` | команда `run_bot` (long polling), обработка апдейтов: привязка клиента, меню |
| `public` | публичный сайт: главная, расписание машин, отслеживание груза, контакты |
| `panel` | панель сотрудников (`/panel/`): ops-центр, машины, грузы, клиенты, выдача, ордер на день |

Правило: **вся бизнес-логика живёт в `logistics/services.py` и `notify/services.py`**. Views, бот и админка вызывают сервисы и не меняют статусы напрямую.

## 5. Модель данных

**Client** — клиент
- `code` — уникальный, авто: `GW-0001`, `GW-0002`… (последовательно, без переиспользования)
- `name`, `phone` — уникальный, хранится в E.164 (`+79991234567`)
- `telegram_chat_id` (nullable), `telegram_link_token` (случайный, уникальный, для deep link `t.me/<bot>?start=<token>`)
- `notes`, `created_at`
- свойство `has_telegram`

**Truck** — машина / рейс
- `number` — уникальный номер рейса, авто: `R-2026-001` (год + порядковый)
- `plate` (госномер, необязательно), `route` (по умолчанию «Уссурийск → Владивосток»), `driver_phone` (необязательно)
- `status`: `loading` (грузится в Уссурийске) → `in_transit` (в пути) → `arrived` (прибыла на склад) → `closed` (разгружена, все грузы выданы или рейс закрыт вручную)
- `loading_starts`, `departure_date` (план), `eta` (ожидаемая дата прибытия), `departed_at`, `arrived_at`
- `is_public` (показывать в публичном расписании, по умолчанию да), `comment`

**Cargo** — груз (одна позиция клиента в машине)
- `client` FK, `truck` FK (nullable, пока груз ещё не распределён в машину)
- `article` — номер товара (артикул), строка до 64 символов, обязательный, индекс; по нему ищут груз в панели и на сайте
- `description`, `places` (кол-во мест, ≥1), `weight_kg`, `volume_m3` (decimal, необязательно)
- `amount_due` (руб., decimal, к оплате при выдаче, может быть 0)
- `status`: `received` (принят в Уссурийске) → `loaded` (погружен) → `in_transit` → `ready` (на складе, можно забирать) → `picked_up` (выдан)
- `ready_at`, `picked_up_at`, `picked_up_by` (User FK), `paid` (bool)
- `free_storage_until` (date = `ready_at` + `FREE_STORAGE_DAYS`, по умолчанию 7)

**Notification** — сообщение клиенту
- `client` FK, `cargo` FK (nullable), `truck` FK (nullable)
- `kind`: `departed`, `arrived`, `reminder`, `storage_ending`, `custom`
- `channel`: `telegram` (в v1 только он; поле есть ради v1.1)
- `status`: `pending` → `sent` | `failed` | `skipped` (у клиента нет Telegram)
- `text`, `attempts`, `last_error`, `created_at`, `sent_at`
- уникальность: одно уведомление одного `kind` на (`client`, `truck`) в день, чтобы не задваивать

**DailyOrder** — ордер на день (замена листочка)
- `date` (уникальная), `created_at`, `created_by` (User, nullable — если создан автоматически)

**DailyOrderLine** — строка ордера (одна на груз)
- `order` FK, `cargo` FK, снимок на момент формирования: `article`, `client_name`, `phone`, `weight_kg`, `places`, `amount_due`, `days_waiting`
- `call_status`: `pending` (не звонили) → `reached` (позвонили) | `no_answer` (не смогли дозвониться). Можно менять повторно в течение дня
- `promised_date` (nullable, «приедет …»), `comment`, `updated_by`, `updated_at`
- уникальность (`order`, `cargo`)

**ContactAttempt** — журнал звонков (пишется при каждой отметке в ордере)
- `client` FK, `cargo` FK (nullable), `staff` FK User, `outcome`: `reached` | `no_answer`
- `promised_date` (nullable), `comment`, `created_at`

Сотрудники — стандартные Django User. Две группы: `Менеджер` (всё) и `Склад` (выдача, ордер на день, просмотр).

## 6. Правила статусов (доменные сервисы)

- `truck_depart(truck)`: `loading` → `in_transit`, ставит `departed_at`. Все грузы машины → `in_transit`. По одному уведомлению `departed` на каждого клиента машины (агрегировано: один клиент с 3 грузами получает одно сообщение).
- `truck_arrive(truck)`: `in_transit` → `arrived`, ставит `arrived_at`. Грузы → `ready`, `ready_at = now`, считается `free_storage_until`. Уведомление `arrived` каждому клиенту (список его грузов, итоговая сумма к оплате, адрес и часы работы склада из настроек).
- `cargo_pickup(cargo, staff, paid)`: `ready` → `picked_up`. Если в машине `arrived` все грузы выданы, машина → `closed`.
- Недопустимый переход — `InvalidTransition`, ничего не меняется. Всё в `transaction.atomic`.
- Уведомления ставятся в очередь (`pending`) внутри той же транзакции. Отправку делает `send_notifications`, не сам запрос.
- Если у клиента нет Telegram, уведомление сразу `skipped`, а груз попадает в ордер на день.

## 7. Ордер на день (замена листочка)

Ордер на дату D формируется автоматически командой `build_daily_order` (утром, по таймеру) или кнопкой «Сформировать ордер» в панели. Повторное формирование **добавляет** новые строки и не трогает уже отмеченные.

В ордер попадает каждый груз в статусе `ready`, если выполняется одно из условий:
- у клиента нет Telegram, или последнее уведомление `skipped`/`failed`;
- груз лежит ≥ `CALL_AFTER_DAYS` (по умолчанию 3) дней после `ready_at`;
- в прошлом ордере строка осталась `no_answer` или `pending` (переносится автоматически).

Исключения: строки с `reached`, у которых `promised_date` ≥ D (клиент обещал приехать). Менеджер может вручную добавить любой готовый груз (поиск по артикулу или телефону) и убрать строку.

Экран ордера — таблица: № · артикул · клиент · телефон (`tel:`-ссылка) · вес, кг · мест · к оплате · дней на складе · статус · действия. Две крупные кнопки статуса в строке: **«Позвонили»** (необязательно указать дату приезда и комментарий) и **«Не дозвонились»**. Отметка уходит через HTMX без перезагрузки и пишет ContactAttempt. Сверху счётчики: всего / позвонили / не дозвонились / осталось. Фильтр по статусу. Ордер можно распечатать (print-CSS, чёрно-белый A4) и выгрузить в `.xlsx`. Ордера за прошлые дни открываются только для чтения.

Если груз выдан в течение дня, строка помечается «выдан» и уходит вниз.

`daily_reminders` (раз в день утром): клиентам с Telegram, у которых груз `ready` ≥ 2 дней, шлёт `reminder` (не чаще раза в 2 дня). За 1 день до `free_storage_until` шлёт `storage_ending`.

## 8. Telegram-бот

- `/start <token>` — привязка по deep link (ссылку/QR сотрудник показывает или отправляет клиенту из карточки клиента).
- `/start` без токена — бот просит «Поделиться номером» (кнопка request_contact). Если телефон есть в базе, привязывает чат. Если нет, сообщает «номер не найден, обратитесь к менеджеру».
- Меню (reply-клавиатура): **Мои грузы** (статусы, машина, ETA, сумма), **Расписание машин** (ближайшие машины `loading`/`in_transit`), **Адрес и часы склада**.
- Если чат заблокировал бота (403), отправщик помечает `failed`, обнуляет `telegram_chat_id`, груз попадает в следующий ордер.

## 9. Публичный сайт

- `/` — главная: что мы делаем, как это работает (4 шага), блок «Ближайшие машины», форма «Где мой груз», кнопка бота, контакты.
- `/schedule/` — расписание: машины `loading` и `in_transit` (+ прибывшие за 3 дня): рейс, маршрут, статус, дата отправки, ETA, прогресс-полоса. Без данных клиентов.
- `/track/` — форма «код клиента или артикул + последние 4 цифры телефона» → список грузов клиента. Rate limit: 10 попыток в минуту с IP (кэш Django). Ошибка всегда одинаковая: «не нашли».
- `/contacts/` — адрес, часы, телефон, карта-ссылка.

## 10. Панель сотрудников `/panel/`

- **Ops-центр (дашборд)** — в стиле тёмного диспетчерского экрана (см. DESIGN.md): верхняя строка KPI, слева конвейер статусов, в центре **3D-сцена**: площадка погрузки в Уссурийске, дорога и склад во Владивостоке; машины движутся по реальному прогрессу, коробки грузятся и выгружаются по блокам склада (мобильный вариант — плоская схема маршрута), справа панель деталей выбранной машины, снизу список машин и таймлайн отправок/прибытий за день.
- **Машины**: список с фильтром по статусу. Карточка: шапка со статусом и большой кнопкой следующего шага («Отправить машину» / «Машина прибыла»). Кнопка открывает подтверждение: сколько клиентов получит сообщение и сколько попадёт в ордер на звонок. Ниже таблица грузов, добавление груза (поиск клиента по телефону/коду, создание на лету) и импорт манифеста из Excel.
- **Грузы**: поиск и фильтры.
- **Клиенты**: поиск по телефону/коду/имени. Карточка: грузы, уведомления, звонки, ссылка и QR для привязки Telegram.
- **Выдача**: поле поиска (код/телефон) крупно → готовые грузы клиента → «Выдать» с отметкой оплаты.
- **Ордер на день**: см. раздел 7.

Импорт манифеста (`.xlsx`): колонки `артикул, телефон, имя, описание, мест, вес, объём, сумма`. Неизвестный телефон создаёт клиента. Сначала предпросмотр с ошибками по строкам, потом подтверждение. Импорт атомарный.

## 11. Настройки (env)

`SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `WAREHOUSE_ADDRESS`, `WAREHOUSE_HOURS`, `WAREHOUSE_PHONE`, `FREE_STORAGE_DAYS=7`, `CALL_AFTER_DAYS=3`, `WAREHOUSE_CITY=Владивосток`. Без `TELEGRAM_BOT_TOKEN` отправщик работает в dry-run (логирует, помечает `sent` с пометкой dry-run в `last_error`).

## 13. Definition of Done v1.0

- Сценарий целиком работает на демо-данных (`python manage.py seed_demo`): создать машину → добавить/импортировать грузы → «Отправить» → «Прибыла» → клиенты с Telegram получили сообщения → сформирован ордер на день, отмечены «позвонили / не дозвонились», ордер распечатан и выгружен в Excel → выдача → машина закрыта.
- Бот привязывает клиента по ссылке и по номеру, отвечает «Мои грузы» и «Расписание».
- Публичные страницы и панель корректно выглядят на ширине 375px и ≥1280px.
- `pytest` зелёный, `ruff check .` чистый. Сервисы статусов, формирование ордера, отправщик и импорт покрыты тестами.
- `docs/DEPLOY.md`: как поднять на VPS (gunicorn, nginx, systemd-юниты для бота и таймеров).
